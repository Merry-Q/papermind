RAG: Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks

RAG 通过结合预训练参数化记忆（BART）与非参数化外部记忆（Wikipedia 索引），在知识密集型任务中实现了可更新、可解释且事实性更强的生成，解决了纯参数模型无法更新知识和产生幻觉的局限。

知识放在哪里，更新就发生在哪里

纯参数模型把知识隐含在权重中，直接检查和修改特定事实很困难。RAG 将参数记忆与可替换的非参数文档索引结合，让模型能在生成时访问外部证据。

方法：RAG 架构概览

RAG 模型由两个核心组件构成：(1) 检索器 pη(z|x)，它根据输入查询 x 返回文本段落的分布；(2) 生成器 pθ(yi|x, z, y1:i−1)，它基于输入 x、检索到的文档 z 以及已生成的 token 来预测下一个 token。

具体实现中，检索器使用稠密段落检索（DPR）技术，通过最大内积搜索（MIPS）从 Wikipedia 稠密向量索引中找到 Top-K 个相关文档。生成器则采用预训练的 BART-large 模型。这两个组件被组合在一个概率模型中，并进行端到端的联合微调，无需对检索哪个文档进行直接监督。

我们将检索到的文档 z 视为潜在变量 (latent variable)，并通过 Top-K 近似进行边缘化：

p(y|x) ≈ Σ pη(z|x) pθ(y|x, z) 教学示例，非论文训练权重

与以往针对特定任务从头训练的架构不同，RAG 利用了预先训练好且 loaded 了大量知识的组件。这意味着模型在微调前就已具备访问知识的能力。

局限性与假设

  • 预训练的检索器和生成器组件可以直接组合并有效微调。
  • Top-K 近似足以代表潜在的文档分布。
  • 检索器在训练期间保持文档索引固定，仅微调查询编码器。

机制：序列与 Token 的边缘化

RAG-Sequence 假设单文档生成全序列，RAG-Token 允许每 Token 切换文档，两者通过边缘化概率整合不确定性。

当前模式：全局文档承诺

形式化：RAG-Sequence 与 RAG-Token 的边缘化

为了训练检索器和生成器，RAG 将检索到的文档视为潜在变量，并通过两种不同的方式进行边缘化处理。

RAG-Sequence

RAG-Sequence 模型假设同一个检索到的文档负责生成整个目标序列。在数学上，它将文档 z 视为单一潜在变量，通过对 Top-K 个文档的生成概率进行加权求和（边缘化）来计算最终序列概率 p(y|x)。这意味着模型在生成整个句子时必须“承诺”于某一个文档。

pRAG-Sequence(y∣x)≈∑z∈top-kpη(z∣x)∏i=1Npθ(yi∣x,z,y1:i−1)p_{\text{RAG-Sequence}}(y|x) \approx \sum_{z \in \text{top-}k} p_\eta(z|x) \prod_{i=1}^{N} p_\theta(y_i|x, z, y_{1:i-1})

注意：求和符号 ∑\sum 在最外层，覆盖了整个序列概率的乘积。

RAG-Token

RAG-Token 模型则更加灵活，允许为每个目标 token 绘制不同的潜在文档。在生成每个 token 时，模型都会对所有 Top-K 文档的预测分布进行边缘化。这使得生成器可以在回答的不同部分引用不同文档的内容。

pRAG-Token(y∣x)≈∏i=1N∑z∈top-kpη(z∣x)pθ(yi∣x,z,y1:i−1)p_{\text{RAG-Token}}(y|x) \approx \prod_{i=1}^{N} \sum_{z \in \text{top-}k} p_\eta(z|x) p_\theta(y_i|x, z, y_{1:i-1})

注意：求和符号 ∑\sum 在乘积 ∏\prod 的内部，针对每个 token 独立进行。

对于序列分类任务（目标序列长度为 1），这两种模型是等价的。作者指出，这两种公式都是通过 Top-K 近似来处理潜在变量的 。

训练：冻结编码与解码策略

RAG 通过最小化负边缘对数似然进行端到端训练。为降低计算成本，文档编码器在训练期间保持冻结。解码阶段，RAG-Token 可直接使用束搜索，而 RAG-Sequence 需采用近似策略。

1. 训练配置与成本权衡

训练目标是最小化每个目标的负边缘对数似然（negative marginal log-likelihood）。模型将检索到的文档视为潜变量。

当前策略： 冻结文档编码器和索引。
理由： 避免像 REALM 那样定期更新索引的高昂成本。实验发现此步骤对于获得强劲性能并非必要。
优化对象： 仅微调查询编码器 (BERTq) 和 BART 生成器。

核心结论

  • 训练效率： 冻结 BERTd 避免了昂贵的索引重建，仅微调 BERTq 和 Generator 即可达到 SOTA。
  • 解码差异： RAG-Token 可视为标准自回归生成器；RAG-Sequence 需对每个文档运行束搜索，并处理未出现在束中的假设概率（Thorough）或近似为零（Fast）。

Result: State-of-the-Art Open-Domain QA

实验结果显示，RAG 在所有四个开放域 QA 任务上均设定了新的最先进记录（TriviaQA 仅在可比的 T5 分割上）。RAG-Token 和 RAG-Sequence 在 NQ 上的精确匹配（EM）得分分别为 44.1 和 44.5，超过了 DPR (41.5) 和 T5-11B+SSM (36.6)。

与需要昂贵专用预训练（如 salient span masking）的 REALM 和 T5+SSM 不同，RAG 无需此类预训练即可取得强劲结果。RAG 的检索器初始化自 DPR，但整体系统表现优于使用重排序器和抽取式阅读器的 DPR QA 系统。

生成式答案相比抽取式答案具有优势：即使检索到的文档包含线索但未 verbatim 包含答案，RAG 仍能生成正确答案。数据显示，在 NQ 测试集中，当正确答案未出现在任何检索文档中时，RAG 仍能达到 11.8% 的准确率，而抽取式模型在此类情况下得分为 0%。

结论

当索引时间与查询对象的时间匹配时，RAG 能正确回答 70% (2016) 或 68% (2018) 的问题。当索引时间不匹配时，准确率大幅下降至 12% 或 4%。这证明模型的知识主要来源于索引而非参数记忆。

边界：索引依赖与检索坍缩

RAG 受限于外部索引的质量与偏差，且在低事实需求任务中可能出现检索坍缩，退化为纯参数模型。

系统行为分析

在高事实需求任务中，检索器根据输入查询动态检索不同文档。生成器有效利用检索到的上下文，梯度信号能够反向传播至检索器，维持系统的端到端优化。

外部索引的双刃剑效应

RAG 的核心优势在于使用原始文本作为外部记忆，但这直接引入了数据源的偏差。

  • ⚠️
    事实性继承：若 Wikipedia 等索引包含错误，模型将直接生成错误内容。 (S169)
  • ⚠️
    潜在滥用：可能被用于生成新闻误导内容或自动化垃圾邮件。 (S169)
  • ✅
    可解释性：原始文本记忆允许人类读取和动态更新索引。 (S163)

局限性与启示

RAG 并非万能架构。在应用时需评估任务对事实检索的依赖程度，并对外部数据源进行严格的质量控制。

带着边界理解这篇论文

RAG 的性能高度依赖外部索引（如 Wikipedia）的质量，索引中的偏差或不实信息会直接传递给模型。

在事实信号较弱或目标序列较长的任务（如故事生成）中，可能出现'检索坍缩'，导致模型退化为纯参数化生成。

FEVER 任务中 BM25 表现优于可学习检索，表明稠密检索并非在所有场景下都是最优解。

RAG-Sequence 的解码需要近似策略（Thorough/Fast），在长序列生成时可能面临计算效率与精度的权衡。

实验主要基于 2018 年 Wikipedia 转储，对于此后发生的世界知识变化，需手动更新索引。
