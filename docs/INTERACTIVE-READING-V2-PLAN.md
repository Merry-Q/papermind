# paperMind 交互讲解 V2 修改方案

日期：2026-10-25。状态：方案，未实施。依据：当前源码、27 个已发布场景、用户提供的千问网页端 Attention 成品及其浏览器实测。

## 1. 本轮决策

把呈现链路从“为正文节点补充有限状态 SVG”改为“依据全文证据设计一份文档专属的互动讲解”。全文核心论证完整、原文阅读、右栏知识与 Copilot、用户补充与撤回、个人概念库的业务规则保持不变。

不是把千问 HTML 塞入正文，也不是复制一套固定蓝图皮肤。借鉴其整篇构图、内容驱动交互和真实计算能力，补齐事实与运行校验。

用户已说明样例来自千问网页端直接接收 Skill 提示和论文。不能将差距主要解释为 Codex 的工具调用循环；网页端具体模型、思考预算与内部执行流程未知。

## 3. 产品呈现：稳定工作台中的文档专属作品

默认仍进入交互讲解，可切回原文。工作台导航、右侧 Copilot/知识栏、来源打开方式保持一致。只升级主阅读区。

主阅读区由文档级计划生成：

1. 首屏：核心问题、结论、适用边界和能建立全局关系的主视觉。不得把局部实验结论放大为普遍定律。
2. 连续主线：按论文真实论证组织问题、方法、证据、条件与局限；这些是语义职责，不是每篇固定的五张卡片。
3. 值得操作的段落：交互成为该段解释的主体，旁边只保留必要引导和结论。
4. 详细推导、实验配置、次要证据折叠查阅；核心前提与会改变结论的限制不能藏入折叠层。
5. 每个场景默认画面已有基本解释，用户不操作、不追问也能读完完整核心论证。

不再固定采用“摘要 → 图解 → 原步骤 → 全部段落 → 原页图”的叠加布局。计划为每个原文节点指定主阅读去向：主线、交互内解释、细节层或原文。建立核心论断覆盖表，防止去重时删掉重要论证。

一个场景可以关联多个节点，一个节点也可被多个场景引用。通过稳定 `node_id`、`claim_id`、`scene_id`、`anchor_id` 定位。Copilot 的上下文仍包含原节点与来源，场景只增加当前操作上下文，不替换原始知识上下文。

用户已加入的页面补充继续按稳定节点锚点显示；呈现重生成不得覆盖、丢失或隐式撤回补充。旧锚点失配时保留补充并给出定位回退。

## 4. 先确定交互要解释什么，再选择输入形式

每个候选交互的设计卡必须回答：

- 哪个概念或关系仅靠文字难以理解？
- 用户改变什么，什么条件保持不变？
- 页面按什么公式、数据或逻辑产生结果？
- 操作会让读者观察到什么，帮助建立哪层理解？
- 哪些结果是原文事实，哪些是教学计算，哪些不允许生成？
- 默认画面和复位状态分别是什么？
- 验收时用哪个操作、哪个独立预期判断它真的成立？

只有高亮也可以合格，但必须帮助追踪依赖、路径或条件；“按钮数量多”“发生动画”不直接计为设计通过。不适合交互的段落使用清楚的图文，不为凑数量加入控件。

### Attention 首篇验证设计

| 内容 | 计划呈现 | 可操作与可观察结果 | 证据边界 |
|---|---|---|---|
| 全文主线 | 问题—架构—机制—结果—局限的论证图与连续阅读 | 选择关系能定位相应解释及依据 | 关系类型区分支持、组成、条件，不任意改写为因果 |
| 自注意力 | 小型 Q/K/V 计算实验 | 改 Q/K 后显示点积、缩放、权重及加权输出；V 改变输出，不改变权重 | 小矩阵明确为教学示例，公式来自论文；不冒充训练权重 |
| 掩码与多头 | 同一例子的可见连接与分头视图 | 掩码排除未来位置；切头展示各头投影及结果如何组合 | 示例投影需明确；不能暗示多头必然学到预设语言职责 |
| 位置编码 | 热力图联动选中位置的曲线与数值 | 改变位置/维度选择，图与值同步；鼠标、触摸、键盘均可选取 | 使用论文公式，展示范围和维度是教学设置；公式之外的性质单独核验 |
| 复杂度 | 连通结构和增长量比较 | 改变 n、d，观察各项表达式及相对增长 | 只展示理论量级或明确假设下的代理量，不标成真实运行耗时 |
| 翻译实验及消融 | 任务/已报告配置筛选、同口径对照 | 切 EN-DE/EN-FR 或选真实实验行，数值、图高、标签同步 | 不自由组合未报告配置，不插值预测 BLEU；缺失值显示未报告 |

以上是内容设计目标，不是强制拆成六个 iframe 或六次模型调用。可根据讲解节奏合并场景。

## 5. 放开创作能力，保留执行与事实边界

### 5.1 新产物契约

保留 V1 的 states/patches 兼容路径，新建 `presentation.v2`，不把旧协议直接放宽：

- `ReadingPlan`：主线、核心论断覆盖、场景与节点映射、主次层级、来源依赖、风格方向。
- `SceneDesign`：用户操作、预期理解贡献、证据种类、输入域、计算/选择规则、可观察输出、复位、操作验收点。
- `SceneArtifact`：HTML、CSS、场景脚本、依赖事实 ID、行为契约、宿主桥接动作、版本与哈希。
- `VerificationBundle`：独立计算用例、来源比对、浏览器轨迹、截图、设计评审与未解决项。

允许原生 input/select、SVG、Canvas 和场景内计算/拖拽/联动。有限状态继续适用于步骤和条件解释，但不再是唯一表达方式。视觉布局可以自由生成，不要求调用固定图表组件；公共部分仅抽取来源、复位、桥接、生命周期等基础能力。

### 5.2 脚本执行

在既有 opaque-origin sandbox iframe 上增加 V2 脚本编译路径；保留 `allow-scripts`，不增加 `allow-same-origin`、表单提交、弹窗、下载或顶层导航权限。

产物装配时用 CSP 禁止网络和外部资源、连接、frame、object、表单和 worker；只允许编译阶段明确授权的内嵌脚本与样式，拒绝任意内联事件属性及动态外部加载。静态规则与浏览器请求拦截共同验证边界。

保留 `event.source`、通道、文档/场景身份和来源/概念 ID 白名单校验。宿主仅接受来源打开、节点导航、打开概念、显式提问、选区、尺寸及就绪等已定义动作；拒绝额外字段、过长文本、过频消息和越界尺寸。来源和提问等宿主动作要求用户主动触发；脚本没有数据库、密钥或写业务表的接口。

`sandbox`/CSP 不能保证 CPU 和内存隔离。验收需检查耗时循环、资源规模、反复初始化和卸载；提供宿主恢复/关闭与正文回退。上线前必须验证失控脚本不会让阅读页无法恢复，不能只凭一条静态扫描通过就默认发布。

### 5.3 三类事实与输出

| 类型 | 可做什么 | 不允许什么 |
|---|---|---|
| 论文报告数据 | 从已核验账本选取、筛选、同口径比较 | 缺失值补齐、随意组合联合实验、改单位/总体/限定词 |
| 公式或教学模型 | 依据明确公式和声明假设计算示例，显示中间量 | 把教学值标成原实验，把量级代理当作实际性能 |
| 结构与论证关系 | 展开前提、反例、分支与适用条件 | 给哲学论证捏造概率、把相关性升级为因果 |

事实账本是只读证据包，原文报告结果由引用 ID 解析显示；不能仅信任脚本自报的数据类型。检验所有会影响事实输出的输入分支：有限配置枚举，连续计算使用独立实现、边界值和性质检查，Canvas 也要校验数值到像素的映射。任意生成脚本的语义无法由 CSP 保证，设计/事实评审仍是发布门槛。

## 6. Agent/Skill 与模型调用

角色表示生成职责，不意味着建立多个常驻 Agent 或每次新增一轮模型调用。

| 职责 | 输入与输出 | 本次修改 |
|---|---|---|
| 文档编排 | 全文论证、图表目录、原文依赖 → ReadingPlan | 从选 2–3 个节点升级为整篇阅读编排 |
| 交互设计 | 计划与证据 → SceneDesign | 先决定操作的解释价值、计算依据和验收点，再写代码 |
| 场景编写 | 文档风格、局部完整证据、设计卡 → 代码产物 | 移除固定蓝灰与仅状态切换约束，允许 V2 受限脚本 |
| 事实复核 | 原始证据、输入域、实际输出 → 支持/矛盾/不足 | 核查派生值、联合配置和比较范围，不只核静态文案 |
| 体验评审 | 默认/操作后/移动端截图与轨迹 → 设计问题清单 | 单独判断关系是否可见、控件是否有解释价值、视觉是否重复文字 |
| 定向修订 | 原产物和整批问题 → 有限范围补丁 | 只修失败职责，保留通过的证据与产物 |

更新项目内 Skill，而非直接复制参考 Skill：扩展 `presentation-plan`、改写 `presentation-author`，增加设计卡与体验评审规范。用户不需要在产品里看到 Agent 名称、Skill 或 JSON。

模型继续采用已接入的阿里系。为创作职责配置独立的 thinking、输出长度和超时选项；只对支持该选项的模型生效。先用同份 Attention 证据对照当前配置与思考配置，记录质量、tokens、墙钟和失败情况，不预先承诺更换模型或增加思考必然改善。

不要求长篇思维过程；只保留可审查的设计决定、事实依赖、代码、操作轨迹和结论。

新版本仅增加呈现计划/产物及发布版本映射，数据库迁移可重复执行且不改写 documents/messages/patches/library/memories 的用户数据。`presentation_version` 与证据、模型、Skill、编译器、检查器哈希共同决定缓存有效性。旧场景不得被误判为 V2。

发布以文档版本为单位原子切换；失败的 V2 草稿不覆盖现有已发布页面。新文档如交互生成失败，显示明确的讲解正文回退，不能声称交互已完成。用户补充和对话不进入共享内容缓存。

## 8. 质量验收：四条独立证据

1. **事实**：核心论断覆盖；来源可打开原页；真实实验配置严格对应；公式计算有独立预期；教学值明确标记；条件/局限保留。
2. **结构**：从首屏到结尾无需对话即可读完核心主线；不重复叠加图文；稳定锚点和用户补充不丢失；不把未完成状态标成完成。
3. **浏览器与计算**：默认、典型、边界、复位均检查；拒绝 NaN/Infinity、错误比例、未变化的假图形、剪裁和失控；Canvas 核验实际像素/命中结果，不以 DOM 哈希代替。
4. **设计体验**：明确指出某次操作让哪一层关系可见；默认图自解释；操作前后差异可读；风格服务内容。人工复核首批成品，模型评审提供依据但不自证通过。

独立预期不能仅由作者同时生成并互相验证。例如 Q/K/V 使用 Python 独立计算及已知边界，实验结果与原表逐行对应，视觉条高与数值比例核对。像素/几何改变只能证明运行，不直接证明学习效果；学习增益需要后续真实用户研究。

代表视口覆盖桌面和 390px/320px 手机；滑块可键盘操作、热力图可点击、尊重减弱动画。不是把所有页面硬塞到一屏。

## 9. 控制生成时间，避免质量升级变成无限生成

- 文档级计划与风格各产生一次，再共享给场景；不为每个图重复读全篇或重新定风格。
- 基于原文页/图表依赖取证并缓存，不固定只看一页，也不重复读取无关页。
- 计划确定后场景并行，沿用当前模型并发额度作为起点；浏览器、OCR、模型分别调度，Copilot 保留容量。
- 事实复核与截图体验复核在生成操作轨迹后并行；可复用的核验只在产物和检查版本一致时复用。
- 每批先完成全部样例并记录问题，冻结该批代码/提示/模型配置，然后集中修订。每轮修订有上限；仍失败则保留旧发布或明确回退，不能降低门槛强行发布。
- 分开记录首次可读时间、完整可用时间、模型调用/排队/检查耗时。暂不承诺节省比例；以既有记录和同材料实测给出差值。
- 长文按论证分层和场景依赖分批生成；全文核心覆盖完成之前，不将局部就绪宣称为首轮完成。当前 20MB/120 页边界不在本次方案中假装已经消除。

## 10. 实施顺序与退出条件

### 第一阶段：Attention 垂直验证

实现 V2 最小完整链路和该论文的连续讲解；千问原文件作为只读参照，现有 paperMind 输出作为基线。先整批验证全部目标场景并记录，再集中修订。验收不以和未知配置的千问网页端做模型能力排名为目标。

退出条件：整篇主线、Q/K/V 真实联动、位置编码查询、真实实验行对照成立；无虚构联合消融值；设计体验与四条检查均通过；原文、右栏和个人库回归通过；报告生成耗时。不能只展示漂亮首屏作为完成。

### 第二阶段：三篇代表材料

Attention + 数据研报 + 哲学/论证材料。分别验证公式探索、真实数据比较、前提依赖。每篇有内容特有的布局/互动理由；不要求三篇刻意换不同皮肤。先全批记录，再集中修订。

### 第三阶段：原十篇跨领域回归

复用现有原十篇材料与已核验解析数据，重生成受影响的呈现，不重跑无关 OCR/对话。一次跑完整批，记录成功/失败/回退、事实、体验、速度及成本；冻结期间不临时改提示。之后集中修订并只重测受影响项和必要回归。

### 第四阶段：默认发布

保留 V1 产物和回滚映射；逐文档切换已通过的 V2，不混用旧新完成状态。必须有发布清单、尚存问题、回退说明、核心业务数据前后核对和一键回滚路径。没有获得新实施指令前，本方案不启动生成和切换。

## 11. 完成定义

用户进入后得到一份围绕全文核心论证组织、视觉明确、可以通过有意义操作探索机制的完整讲解；事实能回查，教学模型与原文结果边界清楚；默认不操作也能阅读，右栏补充与对话仍在原位置；长文不靠删内容提速，失败可回退且不覆盖用户积累。

“更有趣”通过具体设计和操作证据评审，“更促进理解”先证明解释的关系与计算成立，不把测试通过数包装成已测得的学习效果。
