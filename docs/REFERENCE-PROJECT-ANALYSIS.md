# pdf-to-interactive-web 项目分析

分析日期：2026-10-24。仓库：https://github.com/ai-azhou/pdf-to-interactive-web 。分析提交：`f6e651e6f1e9f49836117f0067382aed4f67ea86`。

## 结论

这是给 AI 编程助手使用的 Skill：用一套内容策划、引用和页面规范，引导模型将 PDF 的一节改写为单文件交互 HTML。仓库没有独立的 PDF 转换服务、前端应用、OCR 引擎或模型调用服务。实际 PDF 读取、理解、代码生成与浏览器预览依赖宿主助手及其工具。

适合研究报告讲解、论文学习页、规则查读和一次性互动课件。作为自动化产品的起点，可以借鉴流程与规范；现有检查脚本不足以证明内容准确、离线可用或交互真实有效。

## 工作流程与文件职责

1. 定范围：超过约 30 页优先选一个完整章节。
2. 定读法：叙事沉浸、概念探索、规则查读、数据钻取、论证拆解。
3. 建事实账本：每个关键说法记录 ID、原文页码、原句和转述。
4. 定结构：首屏 30 秒摘要，最多 7 个场景，默认可见不超过 2500 汉字，至少 2 处先猜再看，结尾 3 题自测。
5. 定风格：8 种方向，2–4 幅主要视觉，使用系统字体。
6. 写页面：HTML/CSS/JS 放在一个文件内，要求无外部依赖，提供引用弹层、回到原处、阅读进度、字号、明暗和减弱动画等功能。
7. 自检：脚本结构检查、人工/模型核对 12 处关键说法、条件允许时浏览器检查。

`SKILL.md` 规定流程；`reading-modes.md` 规定阅读方式；`style-presets.md` 给出风格；`page-contract.md` 约定页面及 data-* 标记；`fidelity-checklist.md` 列出转述错误；`prompt-standalone.md` 是简化提示词；`audit_html.py` 用标准库 HTMLParser 和正则输出检查报告。

最值得借鉴的是把“先生成漂亮页面”改为“先建可追溯事实账本，再设计交互”。引用数据通过 `SOURCES` 对象保留页码、原句和转述，但内容并非由检查器对照 PDF 自动验证。

## 检查器实测

测试仅构造本地 HTML 文本并运行 Python 检查器，没有打开这些页面，也没有发起样本里的网络请求。样本和原始报告见 `audit-probes/`。

| 构造情况 | 实际结果 | 含义 |
| --- | --- | --- |
| `data-cite="missing"`，但没有 SOURCES 来源表 | 报告结构全部通过，退出 0 | 缺少来源表时引用校验被跳过 |
| 段落包含“收入100万元”，无引用角标 | 列出 1 个未引用段落，但最终仍报告结构全部通过，退出 0 | 提示项没有进入问题集合 |
| 脚本包含对外部 URL 的 fetch | 报告结构全部通过，退出 0 | 外部资源检查不覆盖动态请求 |
| 外部 script src | 正确列出外部资源问题，退出仍为 0 | 不能直接用退出码作为自动化质量门禁 |

样本仅用注释包含 localStorage、pushState 和系统媒体查询关键词，仍被视为具备相应阅读功能。这证明检查器检测的是字符串出现，不是功能实现。

### 关键实现依据

- `audit_html.py:100–101`：来源 ID 依赖特定正则；`if source_ids` 让来源表为空时的缺失引用检查失效。对来源对象键顺序/构造方式也敏感。
- `audit_html.py:105–108`：阅读功能通过字符串或正则检查；注释和未调用代码也可能命中。
- `audit_html.py:146–159`：未引用数字只被列出，没有加入 `problems`；结尾无论是否存在问题都返回 0。
- `audit_html.py:48–51,94–96`：覆盖 src/href 与部分 style 中的 URL，不等同于完整网络依赖检测。
- `audit_html.py:120–133`：检查是否有自测标记，没有验证恰好 3 道题；首屏仅报告计数；0 幅主视觉不触发数量问题。
- `page-contract.md` 要求零外部依赖；`prompt-standalone.md` 标准版允许 CDN。两个入口的交付保证不同。

这不意味着作者承诺了完整自动事实验证：主流程明确要求抽查原文。风险主要是最终“结构检查全部通过”的表达容易被下游误用。

## 实验数据的证据强度

README 自述使用 5 种材料、2 个模型和多轮核查，并对 2 种材料做各一次有/无 Skill 比较。文档报告准确性与文字量改善，同时给出年报生成耗时 39 分钟对 15 分钟。

当前提交不含输入 PDF、生成 HTML、原始提示记录和逐条核查数据，不能独立复现；每种情况各一次，也不能据此估计稳定错误率。应将这些数字视为作者的探索性结果，不能作为产品准确率或速度保证。

## 面向产品落地的建议（分析推断）

1. 保留“证据账本—交互设计—引用回查”的工作流，适合论文学习工具。
2. 将来源账本独立保存为结构化数据，记录 PDF 哈希、物理页与印刷页映射；只有 page/quote/zh 还不足以自动定位原文区域。
3. 区分结构检查、事实检查和浏览器交互检查，分别给出结果，避免一个“通过”覆盖所有维度。
4. 优先修复来源表缺失检测、未引用事实告警和非零失败退出码，再增加离线网络检查、390px 布局及真实点击测试。
5. 建立少量固定 PDF 和预期事实测试集，重复运行后再比较准确性、用时和成本。

本次没有生成真实 PDF 对应的网页，也没有安装该 Skill，无法对扫描件 OCR、复杂公式/图表、长文档性能或实际学习收益作运行验证。
